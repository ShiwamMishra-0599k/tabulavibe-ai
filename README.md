# TabulaVibe AI

Turn ordinary CSV and Excel files into a data-quality report, KPI dashboard and printable business
report. It runs entirely without paid services. AI commentary is optional and off by default.

- **Upload** `.csv` or `.xlsx` (up to 4 MB, 100,000 rows, 60 columns), or load a synthetic sample.
- **Check quality:** inferred column types, missing and invalid values, duplicates, inconsistent labels. Issues are reported, never silently "fixed".
- **Analyse:** sum, average, count, min and max, grouped by category or by day/week/month/quarter/year, with filters.
- **Explore:** KPI cards with calculation definitions; line, bar and donut charts (each only where suitable); results table.
- **Export:** results CSV, cleaned-data CSV (safe from spreadsheet formula injection), and a print-ready report (save as PDF).
- **Optional AI:** a plain-English summary that receives only aggregated results, never your rows.

Stack: React 19 + TypeScript + Vite + Tailwind CSS v4 + Recharts · FastAPI + Pydantic + pandas + openpyxl ·
pytest, Vitest, Playwright · AWS SAM (Lambda Function URL + S3/CloudFront).

> TabulaVibe AI is a demonstration tool. Files are processed in memory and not stored, but do not
> upload confidential or regulated data.

## Run it locally (Windows PowerShell)

Prerequisites: Python 3.13+ (tested on 3.14.4), Node.js 20+ (tested on 24.15), Git.

```powershell
git clone <this repo> tabulavibe-ai
cd tabulavibe-ai

# Backend (terminal 1)
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000

# Frontend (terminal 2)
cd frontend
npm install
npm run dev
```

Open <http://localhost:5173>. The Vite dev server forwards `/api` to `http://127.0.0.1:8000`.

If port 8000 or 5173 is already taken:

```powershell
# backend on 8010
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8010
# frontend on 5180, pointing at that backend
$env:API_PROXY_TARGET = 'http://127.0.0.1:8010'; npx vite --port 5180
```

Configuration is optional. Copy `.env.example` to `backend/.env` to change limits, CORS origins or AI settings.

## Test

```powershell
# Backend: unit, API, AI-provider and Lambda-event tests + lint
cd backend
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\ruff.exe check .
.\.venv\Scripts\ruff.exe format --check .

# Frontend: type check, lint, unit tests, production build
cd ..\frontend
npm run typecheck
npm run lint
npm test
npm run build

# End-to-end in a real browser (uses your installed Google Chrome; starts both servers on 8011/5181)
npm run test:e2e
```

Set `E2E_BROWSER_CHANNEL=msedge` to run the E2E tests in Microsoft Edge instead.

## Optional AI commentary

Off by default. To enable it, add to `backend/.env`:

```
TABULAVIBE_AI_PROVIDER=gemini
TABULAVIBE_GEMINI_API_KEY=<key from a Google AI Studio project without billing>
TABULAVIBE_GEMINI_MODEL=gemini-3.5-flash-lite
```

Points to know before enabling it:
- On Gemini's free tier, prompts may be used by Google to improve its products. That is why only aggregated figures are sent, and the UI shows the exact payload.
- Free rate limits are set per project in AI Studio.
- If the provider fails or hits its quota, the rest of the app keeps working.
